SQL Queries & Analytics Reference

Core SQL and JPQL queries executed by the application repository layer for technical interview review.

1. Open Tickets Grouped by Priority

JPQL / Aggregate 
SELECT t.priority, COUNT(t)
FROM Ticket t
WHERE t.status != 'CLOSED'
GROUP BY t.priority
ORDER BY COUNT(t) DESC;
Purpose: Identifies the distribution of unresolved incidents by urgency to prioritize triage resources.

2. Engineer Active Workload (JOIN Query)

SQL / INNER JOIN 
SELECT u.name AS engineer, COUNT(t.id) AS active_tickets
FROM users u
INNER JOIN tickets t ON t.assigned_to_id = u.id
WHERE t.status IN ('OPEN', 'IN_PROGRESS', 'WAITING_FOR_USER')
GROUP BY u.name
ORDER BY active_tickets DESC;
Purpose: Calculates the active support burden per engineer to assist in team capacity planning.

3. Average Resolution Time (Timestamp Arithmetic)

SQL / Date Arithmetic 
SELECT AVG(EXTRACT(EPOCH FROM (resolved_at - created_at)) / 3600.0) AS avg_hours
FROM tickets
WHERE resolved_at IS NOT NULL;
Purpose: Measures Mean Time to Resolution (MTTR) in hours across completed support incidents.

4. Defect Escalation Rate

SQL / LEFT JOIN 
SELECT 
    COUNT(t.id) AS total_tickets,
    COUNT(b.id) AS converted_bugs,
    ROUND((COUNT(b.id)::DECIMAL / COUNT(t.id)) * 100, 2) AS escalation_rate_pct
FROM tickets t
LEFT JOIN bug_reports b ON b.ticket_id = t.id;
Purpose: Evaluates what proportion of customer support cases indicate underlying software defects.

Java Object-Oriented Architecture

Direct mapping of Core Java concepts implemented in the backend domain layer.

Abstraction

public abstract class User defines the foundational schema (ID, name, email, department) and contract methods without direct instantiation.

public abstract boolean canBeAssignedTickets();

Inheritance

Concrete entity subclasses (Admin, SupportEngineer, Developer, Employee) extend User using JPA Single-Table inheritance.

class SupportEngineer extends User { ... }

Polymorphism

Subclasses override base methods polymorphically. The business logic executes assignment and troubleshooting checks dynamically.

user.canTroubleshoot() // dynamic dispatch

Encapsulation

Ticket encapsulates its lifecycle state. Properties are mutated strictly through methods like ticket.assignTo(), which enforce invariants and record audit history.

ticket.updateStatus(newStatus, user);
